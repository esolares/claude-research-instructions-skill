# install-update-instructions

A portable skill (Agent Skills format: `SKILL.md` + `scripts/`) that carries a set of always-on
instruction files and installs them for whichever coding agent you use. Everything needed is inside
this directory:

```
install-update-instructions/
  install.sh                 one-step bootstrap: install the skill, then run the installer once
  SKILL.md                   what the agent loads; tells it how to use the skill
  instructions/
    instructions.md          engineering rules (project-agnostic)
    instructions_personal.md domain rules template (optional; --exclude it if not wanted)
  scripts/
    install_update.sh        Claude Code installer (files -> ~/.claude/instructions, block in ~/.claude/CLAUDE.md)
    install_agents.sh        Codex / Gemini CLI / OpenCode / any-rules-file installer
    build_bundle.sh          maintainer tool: refresh the bundle from a directory, write VERSION, make the tarball
  VERSION, MANIFEST.sha256   generated by build_bundle.sh
```

## Install (human or agent)

```bash
tar xzf install-update-instructions-<version>.tar.gz     # skip if you have the directory
cd install-update-instructions
./install.sh --check                # Claude Code, dry run
./install.sh                        # Claude Code
./install.sh --agent codex          # Codex CLI      -> ~/.codex/AGENTS.md (inlined)
./install.sh --agent gemini         # Gemini CLI     -> ~/.gemini/GEMINI.md (@imports)
./install.sh --agent opencode       # OpenCode       -> ~/.config/opencode/AGENTS.md (inlined)
./install.sh --agent all            # every agent whose config dir exists
./install.sh --agent file --file ~/.copilot/AGENTS.md    # any tool that reads a markdown rules file
./install.sh --agent print          # print the block to paste into a UI (Cursor user rules, Windsurf, ...)
```

Add `--check` to any of these for a dry run. Add `--exclude instructions_personal.md` to skip the
domain file. The rules take effect in the agent's next new session.

To hand this to an agent, say: "Install the instructions package at `<path>`: run its
`install.sh --check` for the agent you are, show me the summary, then run `install.sh`."

What gets written:

| | Claude Code | other agents |
|---|---|---|
| skill copy | `~/.claude/skills/install-update-instructions/` | `~/.agents/skills/install-update-instructions/` (Codex user skills dir) |
| instruction files | `~/.claude/instructions/*.md` (mode 600) | `~/.agents/instructions/*.md` (mode 600) |
| rules file | managed block in `~/.claude/CLAUDE.md` with `@instructions/...` imports | managed block in the agent's global rules file (see table above) |

The managed block sits between `<!-- BEGIN global-instructions ... -->` and
`<!-- END global-instructions -->`. Existing content in the rules file is preserved; the block is
replaced in place on later runs. A previous skill copy is moved to `~/.claude/skills_backup/` or
`~/.agents/skills_backup/`.

Codex note: Codex has no import syntax, so the files are inlined, and Codex caps combined
AGENTS.md content at `project_doc_max_bytes` (32 KiB default). The installer warns when the block
exceeds that; set `project_doc_max_bytes = 65536` in `~/.codex/config.toml` or exclude a file.

Environment overrides: `CLAUDE_CONFIG_DIR`, `AGENTS_HOME` (default `~/.agents`), `CODEX_HOME`,
`GEMINI_HOME`, `XDG_CONFIG_HOME`.

## Personalize

`instructions/instructions_personal.md` is a template: put your name in the title and adapt the
domain rules to your field, then rebuild the bundle (below). Keep `instructions.md` generic.

## Update later

Claude Code: `/install-update-instructions` inside the session, or
`~/.claude/skills/install-update-instructions/scripts/install_update.sh [--check]`.
Codex: `$install-update-instructions` (or `/skills`), or
`~/.agents/skills/install-update-instructions/scripts/install_agents.sh --agent codex [--check]`.
To pick up a newer package, run the new package's `install.sh` again.

## Maintain (owner of the instruction text)

Edit the `*.md` files somewhere, then:

```bash
scripts/build_bundle.sh --from <dir>            # refresh bundle, write VERSION, build tarball
scripts/build_bundle.sh --from <dir> --check    # only show what would change
```

The tarball lands in `../../dist/` relative to the skill (`--out DIR` to change), plus an
`install-update-instructions-latest.tar.gz` symlink. Version = `YYYY.MM.DD.<8-char content hash>`.

Requirements on the target: bash 4+, awk, diff, cmp, tar. No network access needed.

Agent conventions used here were checked against the vendors' documentation on 2026-09-11:
Codex (`~/.codex/AGENTS.md`, no imports, `project_doc_max_bytes`, skills in `~/.agents/skills`),
Gemini CLI (`~/.gemini/GEMINI.md`, `@file` imports), OpenCode (`~/.config/opencode/AGENTS.md`),
Agent Skills specification (`SKILL.md` frontmatter).
